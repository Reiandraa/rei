# Google mail OAuth comparison — 20 October 2026

The owner requested comparison with working independent applications, not only Google's sample.

## References inspected

- Mailspring (Foundry376): https://github.com/Foundry376/Mailspring/blob/master/app/internal_packages/onboarding/lib/onboarding-constants.ts
  A real desktop email client. Its Google Desktop registration has both a client ID and desktop client credential. This comparison uses its architecture only: no Mailspring credentials, encrypted constants, code or broad mail/contact/calendar scopes were copied.
- Email OAuth 2.0 Proxy (simonrob): https://github.com/simonrob/email-oauth2-proxy/blob/main/emailproxy.py and https://github.com/simonrob/email-oauth2-proxy/blob/main/emailproxy.config
  Supports real Gmail/other-provider email clients and optional client credentials according to the provider/registration. Its issue 43 concerns Microsoft public clients, not evidence that Google's credential can be omitted.
- Google installed-app library: https://github.com/googleapis/google-cloud-python/blob/main/packages/google-auth-oauthlib/google_auth_oauthlib/flow.py
  `fetch_token` passes its configured client_secret plus code_verifier.
- Google refresh implementation: https://github.com/googleapis/google-auth-library-python/blob/main/google/oauth2/_client.py
  Refresh grant includes client_secret as well as client_id and refresh_token.

## Concrete REI mismatch and applied change

REI supported only Google client_id + PKCE. It could not supply a registered Desktop credential in either grant. Added build-only REI_GOOGLE_DESKTOP_CLIENT_SECRET support and a shared token-form builder for code exchange and refresh. Missing configuration now stops BEFORE opening the browser; it no longer asks users to perform an impossible login. Microsoft retains its existing public-client behavior. Gmail remains REST gmail.readonly; no sending, IMAP full-mail scope, contacts or calendar scopes added. OS-vault user refresh tokens and PKCE/state/destination checks remain.

All callback, mailbox identity and token exchange failures now have fixed stage-specific messages; free-form OAuth response bodies are not logged or exposed. The previous diagnostic binary still had uncovered generic Auth paths. A successful live Google login has NOT been established, so the exact runtime failure is still unconfirmed.

## Publisher credential blocker

Google Cloud Client ID for Desktop shows an enabled masked existing secret, but explicitly says previously generated secrets cannot be viewed/downloaded again. No replacement secret was generated by the agent. Creating or changing an authentication credential is a user handoff. The publisher must use Add secret and save the newly offered Desktop credential JSON outside this repo, then the prepared scripts/build-google-windows.ps1 can inject it for a new build. No credentials should be pasted into chat or committed, including to a private repository.

## UI cleanup in the same patch

Advanced now contains Time zone and Diagnostics. Message recovery is nested under Diagnostics. All Ollama/model/API controls stay in the AI tab. Time zone saves preserve the latest model/provider and enabled/paused state, including changes made after opening the panel.
